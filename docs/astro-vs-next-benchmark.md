# Next.js と Astro の起動・ビルド比較

計測日: 2026-09-14  
環境: Windows 10, Node.js v24.16.0, npm 11.13.0  
同一マシン・同一リポジトリで、置換前（Next.js 16.3.5 静的エクスポート）と置換後（Astro 5 静的出力）を測った。

開発サーバー起動は各フレームワークが出力する Ready 時刻。ビルドは `npm run build` の壁時計。ローカル本番相当は `npx serve` で静的成果物を配信し、`/2026` の HTTP 応答時間を 3 回測った。

## 結果

| 指標 | Next.js | Astro |
|------|---------|-------|
| `dev` Ready（1回目） | 3.0s | 3.192s |
| `dev` Ready（2回目） | 649ms | 661ms |
| `build` 壁時計（1回目） | 115.53s | 41.87s |
| `build` 内訳（1回目） | compile 63s + tsc 30.8s + 静的生成 910ms | Astro 報告 9.87s |
| `build` 壁時計（2回目） | （未計測） | 6.95s |
| 成果物サイズ | `out/` 6.702 MB（333 files） | `dist/` 0.738 MB（23 files） |
| JS 合計 | 798,037 B（16 files） | 404,838 B（10 files） |
| HTML 合計 | 672,027 B（13 files） | 135,698 B（11 files） |
| `/2026` HTML | 99,069 B | 29,061 B |
| `/2026` ローカル応答（1/2/3回目） | 133.2 / 16.0 / 7.5 ms | 194.0 / 6.5 / 6.0 ms |

## 読み方

開発サーバーの Ready はほぼ同等（2回目はどちらも 0.6s 台）。差が出たのはビルド時間と成果物サイズで、Astro の初回ビルドは Next の約 1/3、成果物は約 1/9、JS は約半分、`/2026` の HTML は約 1/3 になった。

ローカル静的配信の応答時間はどちらも数ミリ秒〜百数十ミリ秒で、初回だけディスク／サーバー起動の揺らぎが大きい。フレームワーク差というより `serve` のウォームアップ差に見える。

Next の初回ビルドは Turbopack キャッシュ書き込み失敗の警告が出ていたので、実作業の上限に近い値として読む。
